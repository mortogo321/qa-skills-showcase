# Test Cases — Login

Application under test: https://www.saucedemo.com
Related requirements: REQ-AUTH-01 (login), REQ-AUTH-02 (lockout)

| ID | Title | Precondition | Steps | Expected Result | Priority | Type |
|---|---|---|---|---|---|---|
| TC-LOGIN-001 | Successful login with valid standard user | Browser open at login page; no active session | 1. Enter `standard_user` in Username. 2. Enter `secret_sauce` in Password. 3. Click Login. | User is redirected to the Products (inventory) page; page title shows "Products". | Critical | Functional / Positive |
| TC-LOGIN-002 | Login rejected for locked_out_user | Browser open at login page | 1. Enter `locked_out_user` in Username. 2. Enter `secret_sauce` in Password. 3. Click Login. | Login is blocked; error banner reads "Epic sadface: Sorry, this user has been locked out." User remains on login page. | Critical | Functional / Negative |
| TC-LOGIN-003 | Login rejected with incorrect password | Browser open at login page | 1. Enter `standard_user` in Username. 2. Enter an incorrect password (e.g. `wrong_pass`). 3. Click Login. | Login fails; error banner reads "Epic sadface: Username and password do not match any user in this service." No session is created. | Critical | Functional / Negative |
| TC-LOGIN-004 | Login rejected with unregistered username | Browser open at login page | 1. Enter a non-existent username (e.g. `no_such_user`). 2. Enter `secret_sauce` in Password. 3. Click Login. | Login fails with the same generic mismatch error; no indication of whether the username exists. | High | Functional / Negative / Security-conscious |
| TC-LOGIN-005 | Login rejected with empty username | Browser open at login page | 1. Leave Username blank. 2. Enter `secret_sauce` in Password. 3. Click Login. | Error banner reads "Epic sadface: Username is required." Login is blocked. | High | Functional / Boundary |
| TC-LOGIN-006 | Login rejected with empty password | Browser open at login page | 1. Enter `standard_user` in Username. 2. Leave Password blank. 3. Click Login. | Error banner reads "Epic sadface: Password is required." Login is blocked. | High | Functional / Boundary |
| TC-LOGIN-007 | Login rejected with both fields empty | Browser open at login page | 1. Leave Username and Password blank. 2. Click Login. | Error banner reads "Epic sadface: Username is required." Login is blocked. | Medium | Functional / Boundary |
| TC-LOGIN-008 | Username with leading/trailing whitespace | Browser open at login page | 1. Enter ` standard_user ` (with surrounding spaces) in Username. 2. Enter `secret_sauce` in Password. 3. Click Login. | Login fails (whitespace is treated as part of the username, no implicit trimming); generic mismatch error is shown, no application crash. | Low | Functional / Edge Case |
| TC-LOGIN-009 | SQL-injection-style input is handled safely | Browser open at login page | 1. Enter `' OR '1'='1` in Username. 2. Enter `' OR '1'='1` in Password. 3. Click Login. | Login fails with the standard mismatch error; no bypass of authentication, no stack trace or raw error exposed, no unexpected page state. | Critical | Security / Negative |
| TC-LOGIN-010 | Script-injection-style input in username field | Browser open at login page | 1. Enter `<script>alert(1)</script>` in Username. 2. Enter `secret_sauce` in Password. 3. Click Login. | Login fails with standard error text; input is not executed or reflected unescaped anywhere on the page. | High | Security / Negative |
| TC-LOGIN-011 | Password field masks input | Browser open at login page | 1. Click into the Password field. 2. Type `secret_sauce`. | Characters are rendered as masked dots/asterisks, not plain text, while typing. | Medium | UX |
| TC-LOGIN-012 | Error message clears on retry | Login page showing an active error state from a prior failed attempt | 1. Trigger an error (e.g. wrong password). 2. Correct the credentials. 3. Click Login again. | Previous error banner is dismissed/replaced; successful login proceeds to Products page without residual error text. | Medium | UX |
| TC-LOGIN-013 | Successful login with performance_glitch_user | Browser open at login page | 1. Enter `performance_glitch_user` in Username. 2. Enter `secret_sauce` in Password. 3. Click Login. | Login eventually succeeds and lands on Products page, though page load is noticeably slower than `standard_user`; no error is shown. | Medium | Functional / Positive |
| TC-LOGIN-014 | Login field values are not persisted after failed attempt | Browser open at login page | 1. Enter valid username and an invalid password. 2. Click Login and observe the error. 3. Reload the login page. | Fields reset to empty on reload; no residual credential values are displayed. | Low | UX / Security-conscious |
